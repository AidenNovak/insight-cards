# 第二次核验（独立 agent，无上下文）

第一次试用之后我又做了两轮，都是这个项目里最容易骗自己的两件事：
**信自己的眼睛**，和**信自己的检查工具**。

## 一、我差点把一个假检查发出去

看真实产出时，我觉得 `synapse`（激发）和 `discharge`（击穿）
是"同一个形状"——两张都是发光的分叉树。于是我写了个"形态体检"工具，
用缩略图比两两主题的形状相似度，想给这条盲区加一道检查。

工具跑出来的排名是 `ink ↔ resonance`、`ink ↔ starfield` 最像。
我认为排名不对，就加了个自检："已知最像的 synapse↔discharge 应该排进前八"。
它排第 **87 / 153**，自检失败。

**我当时的反应是"这个指标坏了"。错的是我。** 把两张图放大单独看，
它们明显不同：一个是带发光结点的、自成一体的树，一个是自画面边缘打进来的
细线闪电。"像"只是缩略图尺度上的错觉。

改用**构造出来的基准**（配色不参与种子，所以同主题换配色 = 形状逐像素相同）
重测，指标其实完全正常：同形状 ≥0.011–0.174，不同形状 0.887–1.480，两组不重叠。

但接着测到一条更硬的结论：

| 情形 | 距离 |
|---|---|
| 同主题换配色（几何逐像素相同） | 0.053 |
| **同画法、不同种子（真雷同）** | **0.315** |
| 不同画法的最小值 | 0.721 |
| **同主题换标题（自身变异）中位** | **0.771** |

**跨主题最小值（0.721）低于自身变异中位（0.771）。**
意思是：这个指标认为"两个不同主题"比"同一个主题画两遍"还要像。
它区分不了这两件事 —— 那它就不该存在。

我把这个工具删了，连同四个实验脚本和产物，一行没留。
**一个测不出差异的检查，比没有检查更糟**，因为它会让人以为这块被守住了。

## 二、检查工具全绿，而主题画着别的东西

`doc-check` 会报"机制重复"。我一度以为它在守"两个主题的机制不能是同一件事"。
**它查的是 `connects` 这个字符串有没有重名。**

我做了个实验：把 `echo.mjs` 的内容整个换成 `strata.mjs` 的绘制代码、
只保留 echo 自己的 meta（id/zh/connects/mood 全是 echo 的）。

```
doc-check  → ✓ 文档与代码一致
audit      → 合计：全部通过
```

一个主题可以画着完全不同的东西，两个检查全绿。**这条规则没有工具守着，
也不可能机械化**——"这句话的机制是不是这个形状"是语义判断。
现在这一点写进了 SKILL.md，附带"新主题必须人看图"的要求，
免得下一个人以为检查通过就等于对了。

## 三、第二次核验发现的真缺陷

第一次修"每张卡启停一次浏览器"时，我修的是 `renderCard` 的**能力**
（加了 `browser` 参数），`grid` 和 `readability` 接上了，
但 `audit` / `make-deck` / `contact-sheet` 没接 ——
全量 `audit` 是 18 主题 × 3 次渲染 = **54 次 Chromium 启停**，实跑会崩。

而文档当时写的是"已修掉（全程复用一个浏览器）"。**能力具备了不等于问题消失了。**
三处现已全部接上，全量 `audit` 从崩溃变为 45 秒跑完。

另外修掉三处手抄导致的漂移（README 机制表把 synapse 的机制写成"放电"、
`rng.mjs` 注释说种子含配色——与实现和契约相反、`make-card.mjs` 列了不存在的
`--presets`），并把 **README 的机制表也交给生成器管**——
它的"在演示什么"一列现在直接取主题文件里的 `mood`，不再手抄。
实测：把某行改错，`doc-check` 立刻报错退出码 1。

## 方法上的教训

1. **不要拿"我觉得像"当基准。** 要构造一个不依赖眼睛的基准（这里是：
   配色不进种子，所以同主题换配色必然同形）。我的眼睛在缩略图尺度上骗了我一次。
2. **一个从不失败的检查等于没有检查。** 每个检查我都亲手制造错误验证它会响，
   验完还原并确认回到绿灯。三次自检里有一次暴露的是检查本身没用。
3. **"已修复"要落到每条路径上。** 改了底层能力就宣布问题解决，
   是最容易骗过自己的那种修法。

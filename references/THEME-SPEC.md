# 主题编写规范

> 给要写新主题的人（或 agent）。读完这一页就能写出一个与现有主题同质感的主题。

---

## 一、一个主题是什么

一个 `.mjs` 文件，导出两样东西：

```js
export const meta = {
  id: "starfield",        // 与文件名一致
  zh: "星野",
  en: "Starfield",
  connects: "注视",       // 它表达「连接」的哪一种机制
  mood: "散落的恒星被想象连成一个形状",
  note: "为什么这个意象表达了连接",
};

export function render(ctx, { w, h, rng, palette }) {
  // 在这里画。没有返回值，直接画到 ctx 上。
}
```

**没有 import。** 渲染时 `kit.mjs` 与 `rng.mjs` 的全部导出会被展开到作用域里，
直接用 `glow / rgb / ramp / offscreen / blit / grain / vignette / litStroke / smoothPath /
clamp / lerp / smoothstep / mix / TAU`，以及 `rng.fbm / rng.warp / rng.ridge / rng.next /
rng.range / rng.int / rng.pick / rng.bool / rng.gauss / rng.power / rng.shuffle`。

## 二、接口契约（必须遵守）

| 你拿到 | 含义 |
|---|---|
| `ctx` | 已经按 devicePixelRatio 缩放过。**用 CSS 像素坐标画**，不用管 DPR |
| `w` `h` | 画布尺寸（CSS 像素）。plate 版式下 h 是 864，poster 下是 1440 |
| `rng` | 已按 (主题+配色+文案) 播种。**所有随机都必须走它** |
| `palette` | 见下 |

`palette` 的字段：

| 字段 | 类型 | 用途 |
|---|---|---|
| `base` | `[r,g,b]` | 卡片底色。**画面第一件事就是铺它** |
| `stops` | `[[r,g,b], ...]` | 色阶，从暗到亮。**强度→颜色只走 `ramp(stops, t)`** |
| `glow` | `[r,g,b]` | 最亮处：星点、放电核心、光丝末端 |
| `accent` | `[r,g,b]` | 次亮色：背景辉光、次级结构 |
| `ink` `inkSoft` `muted` `rule` | css 字符串 | 文字用，主题不要碰 |

### 三条硬约束

1. **不许写死颜色。** 一切颜色从 `palette` 派生。写死颜色 = 这个主题不能用别的配色，
   那它就不是模板，只是一张图。要白色就用 `mix(palette.glow, [255,255,255], 0.8)`。

   **这条现在有机器守着**（`bin/audit.mjs` 的"亮部色相"判据：换配色后亮部色相
   至少移动 100°；标定见 `audit.mjs` 里 2b 的注释）。但它守的是"整体"而不是每个像素 ——
   写死的部分若被大面积的正常配色稀释，仍可能混过去。
   写完**自己换两套配色看一眼**，别只等工具给绿灯。
2. **不许用 `Math.random()`。** 必须用 `rng`，否则同一份输入每次渲染都不一样。
3. **只许在开局铺一次底。** 第一行的 `ctx.fillRect(0, 0, w, h)` 是铺底色，可以有；
   之后再整幅盖掉已经画好的东西就不行 —— 那会把前面所有的层次抹平。

   （这条原文写的是"不许 `ctx.fillRect` 之外的整幅覆盖"，按字面读恰好**允许**了
    最常见的 `fillRect` 覆盖，与后半句意思相反。一个试用者指出了这个歧义。
    判据其实很简单：**这一笔是"打底"还是"遮盖"** —— 目的是铺底就可以，
    目的是盖掉已有的东西就不行。）

## 三、让它好看的六个技法

这些是现有主题里反复用到的，也是这一组看起来像"作品"而不是"程序输出"的原因。

### 1. 低分辨率算噪声，再放大贴回来

```js
const nw = Math.round(w / 3), nh = Math.round(h / 3);
const layer = offscreen(nw, nh);
const img = layer.ctx.createImageData(nw, nh);
const d = img.data;
for (let y = 0; y < nh; y++) for (let x = 0; x < nw; x++) {
  const u = x / nw, v = y / nh;
  const t = clamp(rng.warp(u * 3, v * 3, 2, 5));
  const c = ramp(palette.stops, t);
  const i = (y * nw + x) * 4;
  d[i] = c[0]; d[i+1] = c[1]; d[i+2] = c[2];
  d[i+3] = Math.round(t * 255);      // 用 alpha 让暗部真正透出去
}
layer.ctx.putImageData(img, 0, 0);
blit(ctx, layer.canvas, w, h, 0.95, "lighter");   // 亮度叠加，暗部不脏
```

三点值得注意：
- **算 1/3 分辨率**。快 9 倍，放大后的柔化恰好是云该有的样子。
- **alpha 跟着强度走**，不要铺满不透明。`lighter` 叠加时，暗部保持透明，底下的东西才透得出来。
- **用 `lighter`**（加色）而不是默认的 `source-over`。加色不会把画面压灰。

### 2. 域扭曲才是"云"，fbm 只是"团"

```js
rng.fbm(x, y, 5)                    // 同心团块，像棉花
rng.warp(x, y, 2.2, 5)              // 翻卷流动，像云
```

`warp` 把噪声的输入坐标本身用噪声推开，是云、烟、极光类效果的唯一关键。
`ridge(x, y)` 是脊线噪声，适合做有"锋"的结构（纤维、山脉、放电的主干）。

### 3. 光一律走 glow()，不要 shadowBlur

```js
glow(ctx, x, y, radius, color, alpha);
```

`shadowBlur` 慢且会在暗部留下灰雾。`glow` 是径向渐变叠乘，暗部干净。
需要更亮就**叠两层**（大而淡的一层 + 小而实的一层），不要提高 alpha。

### 4. 幂律，不是均匀

自然界的量几乎都是"大量小、极少数大"：

```js
const mag = rng.power(3.4, 0, 1);   // 幂律
const r = 0.34 + mag * 2.5;          // 结果：绝大多数极小，极少数很大
```

均匀分布会立刻暴露成"程序生成"。星点、萤火、树的分支、云团大小都该用幂律。

### 5. 暗部要有东西挡着

星云之所以好看，是因为它**被遮挡**——亮云上压一道黑缝，纵深立刻出来。
只有亮部没有暗部，出来的是彩色棉花。做法：算一条独立的暗带噪声叠乘上去。

### 6. 最后一层颗粒是必需的

```js
grain(ctx, w, h, rng, 0.042, 2);
```

干净到极致的渐变看起来像 PPT。一层很轻的颗粒把它拉回"被冲洗出来的东西"。
用量 0.03–0.06；超过 0.08 会显脏。

## 四、收尾顺序（固定）

```js
render(ctx, { w, h, rng, palette }) {
  ctx.fillStyle = rgb(palette.base);
  ctx.fillRect(0, 0, w, h);     // 1. 铺底

  // 2. 主体（云 → 结构 → 光点，从暗到亮、从大到小）
  // 3. 前景/细节

  vignette(ctx, w, h, 0.45, 1.3);   // 4. 压角
  grain(ctx, w, h, rng, 0.045, 2);  // 5. 颗粒
}
```

`vignette` 的 amount 在 0.42–0.58 之间。低于 0.4 边缘会散；高于 0.6 像加了黑框。

## 五、自检清单

写完一个主题，**渲染出来自己看一眼**，逐条确认：

- [ ] 换一个配色渲染，画面整体跟着变（说明没写死颜色）
- [ ] 同一命令渲染两次，输出**逐字节相同**（说明没漏用 `rng`）
- [ ] 亮度分布不是全画面中间调——有明确的暗部，也有明确的亮点
- [ ] 主体没有被画布边缘硬切
- [ ] 缩小到 200px 宽看，仍能一眼看出是什么（这是缩略图的生死线）
      —— 用 `node Tools/thumb-sheet.mjs <主题...>` 生成并排图看，别凭全尺寸想象
- [ ] 没有一个元素看起来像"贴上去的"（每个发光物周围要有它照亮别处的痕迹）
- [ ] 缩到 200px，它**不像任何仪表读数**（不是波形、不是靶心、不是条形码）
- [ ] 没有触发别的强联想（眼睛、云朵、镜头光斑……见 §6.2）
- [ ] "我画了但看不见"的东西都查过了（多半是 §6.3 的 `lighter` 深色问题）

**缩略图那条要用工具看，不能靠想象。** 它没有自动判据（试过一个形态度量，
分不开"不同主题"与"同主题换种子"，见 `bin/audit.mjs` 顶部），所以只能人看 ——
但至少要看的是**真的 200px**，不是全尺寸图在脑子里缩。
`Tools/thumb-sheet.mjs` 就是为此写的：它把主题按真实配色渲染、缩到 200px、
并排成一张图，你一眼就能看到哪个主题在信息流尺寸下塌掉。

这条不是形式主义。实测过一次：`orbit` 的轨道线是全尺寸下"极细极淡"的美学选择
（1.3 单位宽），到 200px 只剩 0.24 像素 —— 缩略图里只剩两个亮点，
而**它的机制（两条轨道共用一个空的质心）全在那条线上**。
按清单走过一遍就不该漏掉。**"极细极淡"这类判断必须在最终尺寸上做。**

最后一条最容易忽略：**光必须照亮周围**。一个发光点如果周围没被它照亮，
眼睛立刻知道是假的。放电周围要有云被照亮，星云核心周围要有云被烧穿。

§6 里的五条比前面所有技法都更值得读 —— 它们不是"画得不好看"，
是**画错了对象**，而且往往调参数调不出来。

## 六、几何性错误（比技法更难发现）

这些不是"画得不好看"，是**画错了对象**。我写这十八个主题时踩了个遍，
每一条都留下了一张失败的图作为证据。

### 6.1 等距、均匀、完整闭合 = 图表

只要一个图形是**等距排列 + 完美闭合**，它就一定会读成图表而不是自然现象：

| 画成 | 读成 | 修法 |
|---|---|---|
| 正面俯视的等距同心圆 | 声呐 / 靶心 | 加透视（近大远小），让波只在迎光段可见 |
| 一排等距竖线 | 音频波形 | **换图形** —— 参数救不回来，那是波形的定义式 |
| 等厚水平层 | 条形码 / 等高线 | 层厚用幂律（大量薄 + 少量厚），层要会斜、会被切断 |
| 一个区域的整齐点阵 | 坐标纸 / 屏幕像素 | 改成**多晶**：多个取向不同的晶粒 + 晶界 |
| 匀速生长的圆弧边界 | 气泡 | 边界用**直晶面**（段内常数），不是波浪线 |

**根本原因**：自然是**不均匀**的。缺了衰减、缺口、缺了尺度差异，眼睛立刻归类到"图表"。

> 判断方法：把画面缩到 200px。如果它像某个**仪表读数**，就是这个问题。

### 6.2 一个图形特征就能触发另一个联想

- 硬边 + **闭合的亮环** → 眼睛（不是"墨滴"）
- 等距十字四芒 → 相机镜头光斑贴纸（不是"星星"）
- 密集的等距弧 → 声呐
- 一串半圆鼓包 → 云朵（不是"水痕"）

**这些联想比你要表达的意象更强，一旦触发就盖掉原意。**
修法不是调参数，是**去掉那个特征**：墨滴的亮环改画半圈；星的四芒改成长短不一；
波的密度降下来；水痕的鼓包改成扁而浅的。

### 6.3 `lighter` 合成里，深色 + 小 alpha ≈ 不存在

`lighter` 是把颜色按 alpha **加上去**。`stops[1]`（深色）乘 0.1，加在近黑底上
几乎等于零 —— 你以为画了，其实什么都没有。

**凡是"我画了但看不见"的东西，先查这个。** 要可见，颜色至少取到 `stops[2]`。

### 6.4 分段描边会在接缝处留下堆积

`litStroke` 内部是 `lineCap: "round"`。把一条曲线切成十几段、每段单独描边，
**每段的圆头会在接缝处叠出一个亮点**，整条线看起来像虚线或一串珠子。

要做"亮度沿线变化"，正确做法是**按亮度条件把点列拆成几段连续的折线**，
每段一笔画完 —— 而不是画很多小段。

### 6.5 半透明文字要靠 DOM 量位置，不能靠猜

这条是给体检脚本的（见 `bin/readability.mjs`）：量"文字底下有多亮"时，
- 直接量成品卡 → 量到的是**文字自己**，得到 1.15:1 这种荒谬数字
- 按百分比猜文字位置 → 会把页眉页脚算进来，同配色下所有主题量值一模一样
- 正确做法：`renderCard` 返回 `meta.rects`（文字块的真实几何），
  拿无字版在**同一个矩形内**取背景

**量错了对象，会把正确的实现报成错的，也会把错的问题放过。**
